## How the app decides each plan's floor and height

**1. Which floor a plan is.** The app reads this from the drawing itself: first the plan's title ("FIRST FLOOR LAYOUT PLAN" = 1st floor), then the sheet's layout name, then the file name. The Floors page does **not** decide which plan is which floor.
- If the title doesn't name a floor the app knows, the plan gets no floor and is left out of the 3D. That happened with "@(+)6600 LVL" before yesterday's fix. "SERVICE FLOOR" is still one of these.
- If the title names the wrong floor, or none, correct it in **Review → Sheets** by giving that plan its floor.

**2. What each floor is called in Revit.** This is the dropdown beside each ticked floor on the Floors page, for example 1st floor = "Level 1". It's only a name, but it matters a lot: **the heights are stored by that name.**

**3. How high each level is.** In order of priority:
1. A height you typed for that Revit name, on the Floors page or on the Export page under Floor levels. Your value always wins.
2. A height written in the drawings: level marks on sections and elevations, or a title like "@(+)6600 LVL".
3. Nothing given: the 3D view stacks the floor 3 m above the one below, as a preview only, and says so. The Revit export refuses to guess and asks you for it.

## The two mistakes that cause most level problems

**A. Two floors given the same Revit name.** Both floors then get the same height and are built on top of each other. Ankit's Akanistha project has exactly this:
- Ground floor = "Level 2" **and** 2nd floor = "Level 2"
- 1st floor = "Level 3" **and** 3rd floor = "Level 3"

The app warns about this after Analyse, under Issues, "levels".

**B. Floors ticked or named for a different drawing set.** Your "test 1" Floors page is still set up for the Goa drawings: Foundation, Plinth, Level 1 to 5, Level 4 = 12000 (lower than Level 3 = 12600), and Level 0 = 0 with no floor using it. The Akanistha drawing now in that project has Ground, 1st, 2nd, 3rd floor and Terrace. Ground and Terrace aren't ticked, so they get no Revit name or height from you.

## How to set it, step by step

1. **Start a new drawing set**, press **Untick all** on the Floors page.
2. **Tick only the floors this building has**, going by the plan titles: Ground up to the top floor, plus Terrace. Tick Foundation only if a foundation plan is imported.
3. **Give every floor its own Revit name.** The quickest way is the **"Level 0, 1, 2…"** button (Ground = Level 0, 1st = Level 1…) or **"Ground, First, Second…"**. Never give two floors the same name.
4. **Heights:** if the drawings give them, leave the boxes empty. If not, type each one, or type the floor-to-floor height (e.g. 3000) and press **Fill heights**. Each height is in mm from the drawings' ±0, and each floor must be higher than the one below it.
5. **"The lowest floor's columns start from ___":** the height where the bottom floor's columns begin (for example the foundation top, −1200). If you leave it empty, those columns are listed as "needs a decision" instead of being guessed.
6. **Analyse.** Afterwards, check **Review → Issues** for "levels", and **Export → Floor levels**. Anything red there still needs a height.

One tip: when you replace a project's drawings with a different building, as you did in "test 1", redo steps 1–4. The Floors page keeps the previous building's floors and heights.

## How the app sees columns that stop

Each floor's columns are built from **that floor's own plan**, rising from the floor below up to that floor. A column that stops at the 2nd floor is drawn on the 2nd floor plan but not on the 3rd floor plan, so the app already builds it only up to the 2nd floor. No hatch is needed for that.

## What the app reads today

It reads the usual legend way:

```
[hatch sample]  *THUS MARKED RCC COLUMN ENDS AT THIS LVL.
[hatch sample]  *THUS MARKED RCC COLUMN THROUGH.
```

- It finds the legend row, takes the hatch sample just **left of the words**, and finds that same hatch (same pattern and layer) on the plan, including inside blocks.
- Every column inside such a hatch gets the note **"RCC column ends at this level"** (or "continues above"), shown in Review. The Issues list counts them.
- It notes it; it doesn't change what's built, for the reason above.

**Its limits:**
- The row must say **"THUS MARKED"**.
- The words must say **"ENDS"** or **"THROUGH"**. Other wording, like "COLUMN STOPS", "TERMINATES" or "UP TO THIS LEVEL", isn't recognised yet.
- A hatch with no legend row means nothing to the app. It never guesses what a hatch means.

## Why not a cloud with "SC"

- In structural drawings a cloud means **a revision**. The consultant and anyone else reading the drawing would take it as a change.
- "SC" can be read as a **column mark**, since many consultants use C/SC prefixes for columns, so it could create a fake column or clash with a real one.
- It means editing the consultant's drawing, which you'd have to redo on every new issue of that drawing.

**Better:** ask the consultant (or add yourself) one legend row in the standard form above, with a hatch sample to the left of the words, and use that same hatch on the stopping columns. Every drafter understands it, and the app reads it.
