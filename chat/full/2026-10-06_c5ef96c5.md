**Claude** · 2026-10-06 07:36

Yes, that's the idea. **The CAD gives the position of each element and the Excel gives its size and level. The mark (B-34, C-12, S-4A) is what links the two.**

## What each source provides

| | **From the CAD (the analysis)** | **From the consultant's Excel** |
|---|---|---|
| **Columns** | Centre point, rotation (which way it faces), mark | Width × depth, grade, base/top level |
| **Beams** | Centreline (start and end, curves too), mark, which columns it joins | Width × depth, level, Top of Beam Offset (stepped or sunk beams) |
| **Slabs** | Panel outline, cut-outs, which panel carries which mark, which panels are sunk | Thickness, sunk depth |
| **Slab folds** | Location of the paired red lines | Only listed for checking |
| **Walls** | Outline or centreline | Thickness, base/top level |

The CAD is the only place that says where things are. The Excel is the only place that reliably says how big they are and at what height. Neither can build the model alone.

## The workflow, step by step

1. **Get the CAD for each floor.** Run the analysis on each floor's drawing. Each floor gets its own folder with `model.json`.
2. **Generate the Excel from those folders** with `make_schedules.py --from ...` and send it to the consultant. It's pre-filled in grey, so they only check, correct, and fill in the yellow cells (missing depths, levels, grades).
3. **Consultant returns the filled Excel.**
4. **`make_sizes_csv.py`** turns the Excel into `sizes.csv`. Put a copy in each floor folder.
5. **Run `build_model.py` in Revit** (through Rhino.Inside), once per floor. For each element it:
   - takes the position and centreline from `model.json`;
   - looks the mark up in `sizes.csv` and uses the Excel's size and offset;
   - falls back to what the drawing's own printed schedule said if the mark isn't in the Excel.

So the order of priority is: **consultant's Excel → schedule printed on the drawing → default size (and the log names every element that got a default).**

## Things to be aware of

- **The mark is everything.** A beam with no tag in the CAD, or a tag the consultant renamed in the Excel (B-34 becomes B-34A), won't match. It gets built at the drawing or default size. Matching is forgiving about format (`B34` = `B-34`, `12` = `C-12`), but not about different names.
- **One mark, one size per floor.** If the CAD has one mark at two different sizes on the same floor, the Excel can only hold one. The Remark column flags these, and the consultant should split them into separate marks.
- **Revit levels must exist first.** The script doesn't create levels yet. The Excel's Levels sheet (SSL heights) is filled in by the consultant but not used. A useful next step would be for the build to create or check Revit levels from that sheet.
- **Some Excel columns aren't used by the build yet:** concrete grade, steel and links, a column's Base/Top Level (columns always run from the floor below to this floor), and stair data. These could be written into Revit as element parameters, which would make the model schedulable for quantities, but that isn't done yet.
- **Sunk slabs stay panel by panel from the drawing.** The Excel can correct a sunk depth, but which panels are sunk always comes from the CAD hatches and the MOFA legend.
- **Revisions:** when the consultant reissues, re-run the analysis on the new CAD, update the Excel, and rebuild that floor with `REPLACE_PREVIOUS = True`. The Revisions sheet tells you which floors to redo.

## In short
The CAD says **where**, the Excel says **what size and what height**, and the mark joins them. The weak point is mark discipline. That should be a hard rule in the consultant standard: every element tagged, and one mark meaning one size.

If you want, the next things worth building are creating levels from the Levels sheet and writing grade and steel into Revit parameters.

## What a foundation drawing usually contains

A typical consultant foundation set has:
- a **footing layout plan**: footing outlines with tags (F1, F2…), the columns sitting on them, and plinth/tie beams;
- a **footing schedule table**: L × B, depth (edge and centre if sloped), founding level or depth below ground, pedestal size, reinforcement;
- sometimes a **raft**, or **piles with pile caps**, instead of isolated footings.

## How each type would fit the current workflow

| Element | Position from CAD | Size/level from Excel or the drawn schedule | Revit element | Effort |
|---|---|---|---|---|
| **Plinth / tie beams** | Same as beams | Same as the Beams sheet, at a Plinth level | Structural framing | **Almost works today.** Run the beam build with the level set to Plinth |
| **Isolated footings** (F1, F2…) | Rectangle + tag, the same logic as columns, just bigger | L, B, depth, **founding level** | Structural Foundation (rectangular footing family) | **Easy.** Mostly reuses the column logic |
| **Sloped/stepped footings** | Same outline | Edge depth + centre depth | Needs a sloped-footing family with those parameters | Medium. The family has to be made or loaded once |
| **Pedestals / column necks** | Column position | Pedestal size, from footing top to plinth | Column from footing top up to plinth | Medium. Columns currently always run "floor below → this floor" |
| **Combined footings** | Closed outline (not a simple rectangle) | Depth, level | Foundation slab, or an in-place/generic family | Medium |
| **Raft** | Outline + cut-outs, the same as slab panels | Thickness, level, thickenings | Foundation slab (a Floor of foundation type) | Easy. Reuses the slab logic |
| **Piles + pile caps** | Pile circles + cap outlines | Pile diameter and length, cap size | Pile and pile-cap families | Harder. Needs families and a cut-off level |

## The one new problem: levels

Above ground, everything hangs off a floor level, plus an offset. **Footings don't sit on a floor level.** Each one has its own founding depth (F1 at −1500, F4 at −2100 where the soil is worse). So the Excel needs a **Founding Level** or **Bottom of Footing** column per footing mark. Columns then also have to start from the footing top, not from a level.

## What I'd add to the Excel (once you decide to go ahead)

A **Footings** sheet with these columns: Mark, CAD tag, Type (Isolated / Combined / Raft / Pile cap), Length, Width, Edge depth, Centre depth (if sloped), Founding level, Pedestal size, PCC thickness, Concrete grade, Remark.

The consultant standard would also need to say: a footing layer named consistently (e.g. `FOOTING`), every footing tagged, and the footing schedule printed on the drawing in the same table style as the beam schedule. Then the extractor can read it directly, as it already does for beams and slabs.

## Where it stands today

**Already general:**
- **Layer names live in [config.json](cad2revit/config.json), not in the code.** A new consultant's names can be mapped without code changes.
- **Elements are recognised by their geometry:**
  - a column is a closed rectangle;
  - a beam is a pair of parallel faces or a centreline;
  - hatch fill is recognised by its pattern;
  - legends and stray debris are found and left out.
- **Drafting differences are handled:** blocks, columns drawn as loose lines, rotated wings.

**Still tied to this one consultant:**
- **Layer names:** the lists (`BEAM NO (H)`, `R.C.C. PARDI`, `beam sch. text`…) are this consultant's.
- **Schedule tables:** the reader expects this consultant's exact row layout ("read from the right as width, depth, prefix, marks").
- **Mark prefixes:** `mark_prefixes` doesn't even include EB/HB yet.
- **Sunk-slab hatches:** the hatch-pattern → depth table is the MOFA legend. That's fine only if every consultant uses your legend.

## How to make it work for any consultant

**1. Recognise elements by what they look like, not what they're called.**
- Layer names vary between consultants; geometry doesn't. For footings, a closed outline 1–5 m across with a column centre inside it is a footing on any consultant's drawing. Piles are circles grouped under a cap outline.
- The layer name becomes only a hint.

**2. Consultant profiles, plus a one-time setup screen.**
- When a drawing comes from a new consultant, the tool lists every layer with a guess: "COL-OUTLINE → column (64 rectangles, 230–1500 mm)".
- You confirm or correct the guesses once. That's saved as a profile (e.g. `profiles/ABC_Consultants.json`) and reused for all their future drawings.
- Today that means hand-editing `config.json`.

**3. Make the Excel the common format between consultants.**
- Every consultant draws schedule tables differently, and reading arbitrary tables will never be 100% reliable.
- So the CAD only has to provide **geometry + tags**, and all numbers (sizes, depths, levels, founding levels) arrive through **your** Excel format.
- If the tool can read the consultant's drawn table, it pre-fills the Excel in grey. If it can't, those cells stay yellow for the consultant to fill. Either way the Revit build sees the same input.

**4. Read tables by their headers, not their position.**
- Find the table by keywords (MARK, SIZE, L, B, D, DEPTH, FOUNDING LEVEL, THK).
- Map those headers through a list of equivalent names ("DEPTH" = "D" = "OVERALL DEPTH").
- Understand common value styles: "230x600", "230 X 600", "600 DEEP".
- Anything it can't read stays blank, never guessed.

**5. Keep the demand on consultants small.** The few rules any consultant can follow without changing how they draft:
- every element tagged;
- one mark means one size;
- millimetres, drawn at 1:1;
- structure on separate layers (any names);
- sunk slabs either use your legend or have their depth written next to them;
- fill in the MOFA Excel.

**6. Test against several consultants.** Collect drawings from 3–4 different consultants, including a foundation drawing from each. Each becomes a test case with known counts (columns, beams, footings, slabs). Every change must keep all of them passing. That's what stops "it works for Reis Magos" from being mistaken for "it works".

## For footings in particular
I'd build footings the general way from the start:
- recognise them by shape, with a column centre inside;
- tags of any prefix (F, IF, CF, PF, PC…);
- founding levels and depths through a Footings sheet in the Excel.

This consultant's foundation drawing would then be just the first test case, not the template.
