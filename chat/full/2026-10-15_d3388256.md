## The answer to "layers first, then table, then mark?"

Don't use a fixed order. Collect evidence from all three, then let them vote. Each source can be missing or wrong in a given drawing set. A fixed order means one bad source spoils everything after it. Votes let the sources check each other.

## The fix, in 4 steps

**Step 1: Tidy every mark the same way (already mostly done).**
Ignore capitals, hyphens, spaces and underline codes, and also drop **leading zeros**: `S-01`, `S01`, `s 1` all become `S1`. Nothing else is assumed here.

**Step 2: Work out what each prefix means, from the drawing's own evidence.** For each prefix (`S`, `SL`, `GB`…), the app collects:

| Evidence | Example | Strength |
|---|---|---|
| **The schedule's title** | Marks listed in a table titled `SLAB SCHEDULE` are slab marks | Strongest: the consultant says it in writing |
| **Where the marks sit on the plan** | Inside slab bays means slab; inside column boxes means column; along beams means beam | Strong: comes from the geometry |
| **The layer name** | Text on `SLAB NO` means slab marks | Medium: layer names can be stale |
| **The built-in list** | `S` usually means slab | Weakest: used only when nothing else says |

## The answer to "layers first, then table, then mark?"

Don't use a fixed order. Collect evidence from all three, then let them vote. Each source can be missing or wrong in a given drawing set. A fixed order means one bad source spoils everything after it. Votes let the sources check each other.

## The fix, in 4 steps

**Step 1: Tidy every mark the same way (already mostly done).**
Ignore capitals, hyphens, spaces and underline codes, and also drop **leading zeros**: `S-01`, `S01`, `s 1` all become `S1`. Nothing else is assumed here.

**Step 2: Work out what each prefix means, from the drawing's own evidence.** For each prefix (`S`, `SL`, `GB`…), the app collects:

| Evidence | Example | Strength |
|---|---|---|
| **The schedule's title** | Marks listed in a table titled `SLAB SCHEDULE` are slab marks | Strongest: the consultant says it in writing |
| **Where the marks sit on the plan** | Inside slab bays means slab; inside column boxes means column; along beams means beam | Strong: comes from the geometry |
| **The layer name** | Text on `SLAB NO` means slab marks | Medium: layer names can be stale |
| **The built-in list** | `S` usually means slab | Weakest: used only when nothing else says |

If they **agree**, the meaning is used. If they **disagree** (say the table says slab but the marks sit along beams), the app doesn't pick one. It asks you in Review.

**Step 3: Match plan marks to table rows.** Match on the tidied mark (step 1) plus the meaning (step 2). `S1` in a bay matches `S-1` in the slab schedule.

**Step 4: Report whatever doesn't match. Never guess it.** Near misses appear as Issues, with a suggestion you confirm:
- "`SL1` is on the plan but has no table row. Did you mean `S1`?"
- "`S-7` is in the slab schedule but not on any plan."

Near misses are never matched automatically. `S1`, `SL1` and `S10` can genuinely be three different slabs.

**Plus a small screen in Review, "Mark prefixes":** one line per prefix, showing what the app decided and why (e.g. "`SL`: slab. Listed in SLAB SCHEDULE, 14 marks inside bays."). You can change any line. Your answer is saved for that consultant, so their next drawing set needs nothing.
