## The 800 mm question, checked in the code
The review was right that it needed checking. Here is what the code actually does:
- **Joining beams to each other** ([extract.py:1207-1301](cad2revit/core/extract.py#L1207-L1301)):
  - A beam end can move up to 800 mm, the `beam_join_snap_mm` setting.
  - It only moves along the beam's own line, to where it actually crosses a neighbouring beam.
  - Pulling an end back inward is limited to 300 mm.
  - An end sitting on a column can't leave that column.
  - It never moves an end sideways.
- **Extending beams to supports** ([extract.py:1305-1386](cad2revit/core/extract.py#L1305-L1386)): a loose end is extended along its own line, up to 800 mm, until it reaches a column, wall or beam. If it reaches nothing, it is left as drawn and a warning is raised.
- **How changes are reported:**
  - Extensions to supports leave a note on each beam ("end extended X mm…").
  - The beam-to-beam join leaves no note on each beam. It only reports a total ("N beams were extended or trimmed…"). This is the real gap: you can't see which beam moved or by how much.

So my "up to 800 mm" was correct as a maximum. But it's a controlled correction along the beam's own line, and that correction is needed. CAD draws beam faces, while Revit needs centrelines that meet so the beams join. Turning it off would break joins in Revit.

**The fix:** keep the correction, but record each move per beam (original end, new end, distance). The review screen should only flag the unusual ones, for example moves larger than half the beam width. Asking a user to approve 400 normal joins one by one isn't practical.
