**Already there, needs finishing**
- **6. Hatches and X boxes:** sunk strips are built from hatches, cantilevers come from their hatch, and X-crossed layers are recognised and cut as openings. What's missing: the sunk depth from the slab table ("S-1 … 600MM SUNK") isn't applied to the slab yet.
- **7. Slabs between beams:** this is already how slabs are made. The architect's background beyond the outer beams is cut off, and a slab goes outside the bays only where a hatch or mark shows a cantilever.
- **8. Layers by shape:** the layer-suggestion step already does this (boxes → columns, X crosses → openings). It can be extended, but shape should only fill in when the layer name is unclear. It shouldn't overrule a clear name.
- **10. Section drawings:** drawn beam sections are read already. Nothing compares them with the table sizes yet. That comparison is worth adding as a flag only.
- **11. Text:** TEXT, MTEXT, attributes, block contents and paper-space layouts are read. Split marks ("C" "-" "2") are handled inside tables but not on plans. AutoCAD TABLE objects aren't read at all.

**Real gaps, worth doing first**
- **1. Merged cells.** The old table reader learned this yesterday for Stilt A. The new reader ([tables.py](../../../../Documents/Structure%20CAD%20to%20Revit/New%20version/building/readers/tables.py)) still misses it.
- **2. Bare marks (ST, SB) in the table's mark column only.** This one is a live error today: the "ST" row's values fall into the S-1 record.
- **9. Column table headers.** Agreed in principle, but this is where the other session broke the readers baseline. In B BLOCK FOUNDATION, C18's depth of 1050 is a real value, and its edit changed it to 12. The rule has to be "take the value under the column whose header says size". A rule that rejects numbers like 1050 would throw away correct values.
- **12. Sanity flags** (beam no deeper than its slab, one mark with two sizes, odd column size). These are flags only, so they can't change geometry. Cheap and safe. "One mark, two sizes" is already a conflict. The others should compare elements with each other, not use a fixed size table, so no office standard gets built in.
- **5. Leaders, span arrows, mark circles.** Hardly read at all now; marks go to the nearest element. This is a real gap, but it changes which element gets which mark, so every plan needs a value-by-value compare.

**Where I'd change the plan**
- **3. "One table reader only".** Removing the old reader is the biggest regression risk on the list, because everything built so far is checked against what it produces. It already counts for less than the new reader (0.8 vs 1.0). I'd keep it running as a check, let the new reader win, and mark any disagreement as a conflict. Retire it only once the new reader matches it on every sample.
