Why it matters

Today the model is redrawn. Every revision redraws it again.

Manual, as we work now

  • Read each size off the printed schedule, mark by mark
  • Place 48 columns, 170 beam segments and 65 slab panels by hand, per floor
  • Re-type reinforcement into Revit, or leave it out of the model
  • A GFC revision repeats most of that work

Automated, once the CAD is right

  • The script reads the DWG layers and the Excel schedules
  • Geometry, marks, sizes, grade and steel land in one pass
  • A revision becomes a re-run and a difference report
  • An audit list names every mark it could not place

How it works

Five steps from DWG to a checked Revit model

1

Read the layers

Column, wall, beam, girder, slab and sunk layers come out as shapes with coordinates.

2

Match every tag to its shape

Each mark text is joined to the nearest element, so C-3 and B-34 attach to real geometry.

3

Join the schedules

Excel rows supply size, thickness, concrete grade and reinforcement for each mark.

4

Place in Revit

Levels and grids first, then columns, beams, floors with their sunk offsets, then the 230 walls.

5

Audit against the sheet

Marks without geometry, geometry without marks, clashes, and Revit schedules compared to the GFC tables.

The three that stop a script dead

Everything else is tidying. These three are structural.

Blocker 01

Slabs have no outlines

The SLAB layer holds six open fragments. There are 65 slab tags and not one closed shape to turn into a Revit floor.

Needed: one closed outline per slab panel.

Blocker 02

Nothing to set out from

No grids and no dimensions in the plan area. The drawing sits about 2.3 km from its origin, with no point shared with the architectural model.

Needed: a grid layer and one agreed base point.

Blocker 03

Beam lines are faces

The multilines are top justified, so every drawn line is a beam face, 115 mm off centre, and nothing says which side.

Needed: one centreline per span.

Findings · slabs and setting out · 4 issues

Slabs and setting out are the thinnest part of the file

Slabs

No outlines to build floors from. The SLAB layer holds six open fragments. The 65 slab tags have no shape to belong to, so floors would have to be traced from beam edges or redrawn.

Sunk depths do not agree. The layers are named 300mm SUNK and 900MM SUNK, while the legend calls for 100, 150 and 400 sunk, plus the pool and deck slabs. Nobody can tell which hatch is which depth.

Setting out

No grid and no dimensions. Columns are numbered 1 to 32, but there is no grid to hang the model on, so the architectural grid has to stand in for it.

No shared origin. The plan sits about 2.3 km from the drawing origin, and no point is agreed with the architectural model, so nothing lines up on import.

Standard · section 03

Drawing setup: seven things fixed before anything is drawn

Units

Millimetres, drawn 1:1, nothing scaled or exploded

Origin

The architect's base point, identical XY on every floor, never re-rotated

Heights

Everything flat at Z = 0, with FLATTEN run before the file is issued

Files

One floor per DWG, named J1153_Wing_Level_STR_YYYY-MM-DD.dwg

Model space

The plan only, with no xrefs, no images and no viewports in it

Housekeeping

OVERKILL run, no duplicated entities, no structural elements inside blocks

Grids

Structural grid on S-GRID, matching the architectural grid line for line

Standard · section 05

How each element is drawn, so a script can trust it

Columns

One closed rectangle per column, at the scheduled size, once only

Walls

Lift walls and pardi walls on S-WALL, never on the column layer

Beams

One centreline per span, justification set to zero, parallel to the grid

Girders

Drawn at the scheduled width, not at a nominal 350 for all of them

Slabs

One closed outline per panel, edges landing on the beam centrelines

Sunk areas

A closed outline on its depth layer, not a hatch on its own

Openings

Openings, stairs and landings as closed outlines on their own layers
